## Conventions (all proofs)
* Non-interactive via Fiat–Shamir over `transcript::Transcript`. The caller passes a **base transcript** `tx: &Transcript` that already contains ssid / params id / public parameters. Each proof forks it (`tx.clone()`), appends `("zk", name)`, then its statement and first-message values, then derives the challenge with `challenge("e")`. Encoding of every appended value must be canonical and fixed-width (spec §10.2; `append_uint`, `append_residue`, `append_sbig`, curve `encode_point/encode_scalar`).
* **Compact proofs**: a proof stores only the challenge(s) and responses. `verify` reconstructs the first message from the verification equation (e.g. `A = t^z · s1^{-e1} · s2^{-e2}`), re-hashes, re-derives the challenge and compares it with the stored one. All range / membership checks stay (cheap checks first, early exit).
* API per module: `pub struct <Name>Proof {..}` with `prove<R: CryptoRng + ?Sized>(rng, tx, statement.., witness..) -> Result<Self>`, `verify(&self, tx, statement..) -> Result<()>`, `encode(&self, ..) -> Vec<u8>` and `decode(bytes, ..) -> Result<Self>` (fixed lengths from `Params`; wrong length / out-of-range / non-canonical → `Error`; negative zero rejected). Statement/witness types are small structs; witnesses are `ZeroizeOnDrop`-friendly and never `Debug`-print values.
* Ranges: `±2^n` means `|z| ≤ 2^{n-1}` (`SRange::pm_pow2(n)`); samples via `SBig::random_in`; verifier uses `SBig::in_range`.
* Secret exponents (masks α, witnesses, λ, p, q) only via `pow_ct` / `FixedBase::pow_ct`; verifier uses `pow_vartime` / `multiexp_vartime` (≤4 bases) on public data. Use `Params` fields, no magic numbers.
* Honest prover whose response falls outside the verifier's range (probability ≈ 2^-ν) must restart with fresh randomness rather than emit an invalid proof.
* Error type: extend `crate::error::Error` only by adding variants (e.g. `VerificationFailed`) — coordinate: the other agent adds variants too, so re-read `error.rs` before editing and only append.
* Tests (`#[cfg(test)]` in-module or `tests/zk_<name>.rs`, reduced `Params` allowed — `Params` fields are pub — plus ignored full-size tests): honest passes; flipping/modifying each field of the proof or statement fails; boundary ± 1 on every range check; wrong witness fails; encode/decode roundtrip; decode rejects bad lengths.
* Run `cargo fmt`, `cargo clippy -p tecdsa-core --all-targets -- -D warnings`, your tests with `--release`. No git commands. Only edit your own files (+ append to error.rs). Another agent is concurrently editing other files; if the build breaks in a file that isn't yours, wait and retry.
* Final report ≤ 10 lines: API, tests, timings at full size (prove/verify), proof sizes, any deviation from the paper or ambiguity.
